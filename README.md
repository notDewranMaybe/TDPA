# 🌾 虫儿食农油，百秒则灰白——从0到1的「查出病」双库RAG搭建教程

> 本项目旨在构建一个基于本地大语言模型（LLM）与 FAISS 向量数据库的农作物病虫害智能问答系统，通过知识检索与模型推理结合，实现本地化、可交互的问答体验。  

---

## 📌 项目简介

随着农业数字化发展，科研人员和农技人员面临大量的农作物病虫害信息。传统手动查找资料效率低，本项目通过构建本地 RAG 系统，实现：

- 数据自动向量化，构建知识库  
- 本地大语言模型推理问答  
- 双库融合：结构化知识与语义问答结合  
- 可通过本地网页（Streamlit）交互访问  

---

## 🛠️ 系统搭建思路

### 1️⃣ 环境准备

首先，需要搭建一个干净的 Python 环境，并安装必要依赖。  
建议使用 Conda 创建独立环境，并安装数据处理、向量化、模型推理和前端所需库。

### 2️⃣ 数据整理与标准化

收集农作物病虫害相关问答数据，包括问题描述、答案信息、可选图片等。  
数据需整理为统一格式（如 CSV 或 JSON），字段规范，便于后续向量化和检索。

### 3️⃣ 数据向量化与知识库构建

- 选择合适的文本嵌入模型，将问题文本或知识内容转换为向量  
- 使用 FAISS 构建本地向量索引  
- 保存索引文件，作为 RAG 系统检索基础  

向量化是系统核心，向量质量直接影响检索准确性和问答质量。

### 4️⃣ 本地大语言模型选择与加载

- 根据语言需求选择模型，如 ChatGLM、Qwen 或 LLaMA  
- 考虑模型大小、性能与内存占用  
- 本地加载模型，为检索结果生成自然语言回答提供能力  

### 5️⃣ RAG 流程设计

- 将向量检索（FAISS）与大语言模型推理整合  
- 检索到的相关知识作为提示，输入给 LLM  
- 输出自然语言回答，实现问答闭环  

RAG 流程可根据需求设计不同策略，如单轮检索、分块检索或多轮推理。

### 6️⃣ 前端交互设计（Streamlit）

- 构建简洁的网页界面  
- 输入问题 → 触发 RAG → 返回回答  
- 可根据用户需求展示附加信息，如图片、参考资料或检索结果  

Streamlit 可快速搭建交互界面，支持本地运行和远程访问。

### 7️⃣ 系统迭代与优化

- 扩展知识库覆盖更多作物和病虫害类型  
- 支持多模态输入（图片、音频）  
- 调整检索与生成策略，提高问答准确性  
- 优化模型加载方式，提升响应速度
