## 📌 项目简介

你是不是也遇到过这样的情况：
- 手头有小型数据但不知道该怎么处理？
- 没服务器电脑没卡但想做Agent？
- 新人入门但不知道从何做起？

「查出病」Is ALL you need!

「查出病」是一个能在**短时间内迅速复现**，支持**自定义数据处理**的双数据库农业病虫害检索增强生成(RAG)智能体。

它可以：

- **处理病虫害知识 → 向量化 → FAISS 双库存储**
- **选你喜欢的本地 LLM（ChatGLM / Qwen / LLaMA）自由回答**  
- **双库融合检索 → 智能生成问答**  
- **Streamlit 网页互动 → 主动给作物查查病**

## 🛠️ 系统搭建思路

### 1️⃣ 环境准备

首先，需要搭建一个干净的 Python 环境，并安装必要依赖。  
建议使用 Conda 创建独立环境，并安装数据处理、向量化、模型推理和前端所需库。

### 2️⃣ 数据整理与标准化

收集农作物病虫害相关问答数据，包括问题描述、答案信息、可选图片等。  
数据需整理为统一格式（如 CSV 或 JSON），字段规范，便于后续向量化和检索。

### 3️⃣ 数据向量化与知识库构建

- 选择合适的文本嵌入模型，将问题文本或知识内容转换为向量  
- 使用 FAISS 构建本地向量索引  
- 保存索引文件，作为 RAG 系统检索基础  

向量化是系统核心，向量质量直接影响检索准确性和问答质量。

### 4️⃣ 本地大语言模型选择与加载

- 根据语言需求选择模型，如 ChatGLM、Qwen 或 LLaMA  
- 考虑模型大小、性能与内存占用  
- 本地加载模型，为检索结果生成自然语言回答提供能力  

### 5️⃣ RAG 流程设计

- 将向量检索（FAISS）与大语言模型推理整合  
- 检索到的相关知识作为提示，输入给 LLM  
- 输出自然语言回答，实现问答闭环  

RAG 流程可根据需求设计不同策略，如单轮检索、分块检索或多轮推理。

### 6️⃣ 前端交互设计（Streamlit）

- 构建简洁的网页界面  
- 输入问题 → 触发 RAG → 返回回答  
- 可根据用户需求展示附加信息，如图片、参考资料或检索结果  

Streamlit 可快速搭建交互界面，支持本地运行和远程访问。

### 7️⃣ 系统迭代与优化

- 扩展知识库覆盖更多作物和病虫害类型  
- 支持多模态输入（图片、音频）  
- 调整检索与生成策略，提高问答准确性  
- 优化模型加载方式，提升响应速度
